# CSS 兼容性诊断

## 先看实际产物

1. 确认最低 Chromium 与真实终端组，未知内核只做风险评审。
2. 同时检查源码、组件库 CSS、插件输出、压缩后 CSS 和运行时注入样式。
3. 在生产构建与真实路径下复现，不以开发服务器通过代替。
4. 查网络是否加载了正确版本，再查级联、计算值、布局和合成。
5. 保存最小 HTML/CSS 复现及目标浏览器截图。

源码未出现某语法，不代表依赖或构建器没有生成它。
产物扫描定位风险，不证明使用路径必然失败，也不证明零命中即可通过。

## 上游版本参考

下表是上游 Chrome 首次支持的常用起点，不承诺厂商完整实现。
具体子特性、标志、部分实现与变更以 [MDN BCD](https://github.com/mdn/browser-compat-data) 为准。

| 特性 | 上游 Chrome 起点 | 低版本处理 |
| --- | --- | --- |
| `@layer` | 99 | 构建期展开并验证级联，或提供非 layer 基线 |
| 独立 `translate` / `rotate` / `scale` | 104 | 谨慎合并为 `transform`，保持顺序和动画语义 |
| `:has()` | 105 | 业务状态类或其他选择器；核对 specificity |
| 尺寸容器查询 | 105 | 基础布局或媒体查询，不等价于容器查询 |
| `sv*` / `lv*` / `dv*` 视口单位 | 108 | `vh`、容器尺寸或经验证的布局替代 |
| `oklab()` / `oklch()`、`lab()` / `lch()` | 111 | sRGB 基线；核对色域映射与对比度 |
| `color-mix()` | 111 | 静态预计算或按业务状态预定义颜色 |

容器 style 查询、滚动状态查询、相对颜色、嵌套、锚点定位等须分别查证。
不要把“容器查询 105”扩展为所有容器查询子能力均在 105 可用。

## 现代颜色与变量陷阱

盘点 `oklch()`、`oklab()`、`lab()`、`lch()`、`color()`、`color-mix()`。
另查相对颜色语法、透明度、渐变插值色彩空间和广色域资产。
普通声明中可先给旧颜色，再给现代颜色；仍需确认两者计算结果。

```css
.badge {
  color: #174ea6;
  color: oklch(45% 0.15 260);
}
```

自定义属性可接受浏览器尚不能用于 `color` 的 token，不能套用同一推断。

```css
:root { --accent: oklch(45% 0.15 260); }
.badge { color: var(--accent, #174ea6); }
```

在不支持 `oklch()` 的引擎，变量已定义，`var()` 的后备并不会自动触发。
替换后到计算值阶段才发现无效，属性可能回到继承值或初始值。
同一属性更早的声明也不保证被重新采用。
后备用于变量缺失或保证无效值等情形，不是通用“颜色不支持”补丁。

```css
:root { --accent: #174ea6; }
@supports (color: oklch(45% 0.15 260)) {
  :root { --accent: oklch(45% 0.15 260); }
}
.badge { color: var(--accent); }
```

`@supports` 或 `CSS.supports()` 只能检查声明/选择器的支持判定。
它们不保证实际绘制正确、颜色对比达标、GPU 合成无误或主题可用。
必须结合 `getComputedStyle()`、交互和截图检查。

## 渐进增强而非全量禁用

先提供能够完成业务的基线，再为已支持能力增加增强。
现代 CSS 出现本身不是失败条件；核查是否存在可靠基线且能实际使用。
不支持的选择器可能使整个规则失效，应将增强规则与基线分开。
不支持 `@layer` 的浏览器会忽略其中规则；不能把全部基础样式仅放进 layer。
展开 layer 必须保留层顺序、普通声明与 `!important` 的不同优先级语义。
构建工具的转换能力必须以使用版本、配置和产物验证，不按插件名称推断。
Autoprefixer 不能把任意现代 CSS 自动变成旧内核等价实现。

## 使用 Tailwind 时的可选分支

本技能不要求 Tailwind，也不因 Tailwind 缺席而引入它。
Tailwind v4 官方核心基线是 Chrome 111、Safari 16.4、Firefox 128。
见 [兼容说明](https://tailwindcss.com/docs/compatibility) 和 [升级指南](https://tailwindcss.com/docs/upgrade-guide)。
若实际最低 Chromium 是 102，不能宣称给 v4 加颜色替换即可全面兼容。
其核心依赖和产物含多种现代 CSS，单点补丁不能替代框架支持范围。
官方对旧浏览器建议保留 v3.4；现有 v4 项目迁往 v3.4 需先征得用户确认。
迁移是依赖与样式行为变更，不是只改版本号。
确认构建插件、主题 token、工具类、插件兼容、preflight 与输出扫描结果。
若不迁移，则明确选择提高最低浏览器、替换样式方案或缩小可支持范围。
不得静默降级包、删除锁文件或承诺未做过的全量转换。

## 布局与滚动

- Flex/Grid：检查嵌套容器的 `min-width: 0`、`min-height: 0` 与内容收缩。
- 长中文、连续英文和文件名：检查换行、截断、溢出提示与复制完整值。
- Grid：按需使用 `minmax(0, 1fr)`，不能用隐藏溢出来掩盖丢内容。
- 滚动：分别检查页面、表格、弹窗和侧栏，避免双滚动或无法触达按钮。
- Sticky：核对滚动祖先、overflow、transform 与容器高度。
- 固定定位：检查 transform 祖先建立包含块后的定位变化。
- 视口：`100vh` 后接 `100dvh` 可作增强，但桌面缩放和面板仍需实测。
- 缩放：布局/字体变化时检查实际使用的代表性缩放及已知风险档位；完整发布验收按支持契约选择，100%、125%、150%、200% 是候选值，不要求每次全部执行。
- DPR：检查分数缩放、细线、图标、表格边框和 canvas 清晰度。

## 字体、表单与层叠

- 使用可获得且有授权的字体；不假定 Linux 安装 Windows/macOS 字体。
- 检查中文缺字、字重替代、基线、行高、数字对齐和字体加载后的重排。
- 图标字体失败时不得使关键按钮失去可见名称；优先核实资产与 MIME。
- 检查原生日期、下拉、复选框的样式与键盘行为，不强求跨系统像素一致。
- 弹窗、菜单、tooltip：检查 clipping、stacking context 与滚动锁定。
- `dialog` 与 top layer：分别验证 API、焦点进入、Esc、遮罩、关闭与焦点归还。
- 不用无限增加 `z-index` 代替层叠上下文分析。
- 独立 transform 改成 `transform` 时，核对动画叠加、顺序和命中区域。

## 主题、可访问性与输出

- 涉及主题/颜色变化时，在项目实际支持的主题中检查受影响的文字、占位符、边框、禁用态、选中态或图表配色；不为无关修改增加主题测试。
- 支持系统色偏好时，也测试手动覆盖与刷新后的主题恢复。
- 保留可见焦点，不仅依赖颜色区分状态；检查高对比或强制颜色环境。
- 遵循减少动态效果偏好，避免动画成为完成业务的前提。
- 打印检查分页、重复表头、固定元素、背景选择和灰度可读性。
- Canvas 检查实际像素尺寸、字体就绪、缩放重绘及导出；CSS 尺寸不等于画布分辨率。
- 不要仅用截图判定可访问性；键盘顺序和语义另行验证。
