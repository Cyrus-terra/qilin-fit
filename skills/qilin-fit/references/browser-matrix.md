# 浏览器与终端基线

## 使用范围

本参考用于确定实际交付范围，不是“所有麒麟与奇安信版本均兼容”的承诺。
先确认终端，再选择构建目标、渐进增强策略和验收矩阵。
上游 Chromium 支持某特性，只能说明实现的可能性，不等于厂商分支与部署环境已通过。

## 已有官方版本证据

| 官方材料 | 可确认内容 | 不可据此推断 |
| --- | --- | --- |
| [2021-07-06 公告](https://www.qianxin.com/news/detail?news_id=1164) | 麒麟应用商店曾上架 Chromium 93 内核的先锋版 3.0 | 所有 3.x、所有渠道、所有 CPU 均采用同一内核 |
| [2022-05-31 公告](https://qianxin.com/news/detail?news_id=4995) | 先锋版曾升级 Chromium 102，并上架麒麟应用商店 | 数字产品版本、当前商店包版本、现场已安装版本 |
| [2024-12-25 公告](https://qianxin.com/news/detail?news_id=12893) | 先锋版曾升级 Chromium 132 | 数字产品版本、稳定渠道与定制渠道同步情况 |

公告是历史发布事实，不是当前下载、维护、安全补丁或每个架构支持清单。
不得把 102、132 填成公告没有给出的产品版本号。
不得把“先锋版 3.0 = 93”的一条历史记录扩展成产品版本换算公式。

## 终端取证顺序

1. 由现场管理员提供“关于”页及完整产品版本，允许时附版本页。
2. 记录 Chromium/Chrome 内核版本及证据来源，不仅记录 UA。
3. 记录安装渠道：应用商店、厂商官网、单位软件仓库或定制安装包。
4. 记录发行渠道与更新策略：先锋、稳定、定制、冻结或其他实际名称。
5. 记录操作系统完整名称、版本、SP、补丁级别及桌面会话类型。
6. 记录 CPU 架构与设备型号；按实际出现的 x86_64、ARM64、LoongArch 等分组。
7. 记录 GPU、驱动、硬件加速状态、字体和输入法版本。
8. 记录相关企业策略、代理、证书、插件及扩展的启用情况。
9. 记录复测日期、测试产物哈希与浏览器更新状态。

不得仅凭“银河麒麟 V10”认定 SP、架构与运行库相同。
不得仅凭 UA 中的 Chrome 字段认定完整能力；UA 可被修改、简化或冻结。
不得为取证收集账号标识、设备序列号、令牌、证书私钥等无关敏感信息。

## 基线记录模板

```text
终端组：匿名组号
OS / SP / 补丁：待确认
CPU 架构：待确认
浏览器产品 / 完整版本 / 渠道：待确认
内核版本 / 证据：待确认
安装来源 / 更新限制：待确认
GPU / 驱动 / 硬件加速：待确认
相关企业策略 / 网络条件：仅记录必要摘要
业务必需能力 / 可降级能力：待确认
实测产物 / 日期 / 结论：待验证
```

## 最低内核如何确定

- 收集所有纳入合同或发布承诺的终端组。
- 以已核实且仍需支持的最小 Chromium 主版本作为语法与 CSS 审核起点。
- 对厂商补丁、策略和架构差异另立实际验证项。
- 若有非 Chromium 内核，单独建目标，不能并入 Chrome 版本号。
- 若存在远程浏览、兼容视图或内嵌 WebView，记录真正执行网页的环境。
- 若内核未知，结论只能是“风险评审/待取证”，不能默认为 102。
- 未知终端可以运行探针辅助识别，但探针命中不构成完整验收。
- 不以单次能力探测推算完整内核版本。

## 工程测试档位

以下只是可选的上游 Chromium 测试档位，不是奇安信产品映射表。
缺少合法可用的旧版浏览器时，记录缺口，不从未知来源下载历史包。

| 档位 | 典型检查重点 | 适用条件 |
| --- | --- | --- |
| 93 | 未支持的现代 CSS、依赖包语法、原生 API 缺口 | 确实存在该内核的目标终端 |
| 102 | 现代颜色、独立 transform、容器查询、动态视口单位 | 已核实最低内核为 102 或进行边界研究 |
| 109 | 新特性边界与框架最低浏览器要求 | 现场有该档位或需要回归对照 |
| 120 | 新旧主题、布局和第三方组件回归 | 现场有该档位或用于中间版本对照 |
| 132 | 较新内核、策略差异、升级前后回归 | 现场核实为该内核，不代表“所有新版本” |

上游自动化浏览器用于定位引擎级问题。
实际奇安信安装包与麒麟真机用于最终验证。
桌面 Chrome、Playwright Chromium 或 UA 仿真都不能替代厂商真机。

## 最小验收矩阵

每行应代表一个真正需要交付的组合，而不只是一个浏览器品牌。

| 组 | OS/SP | CPU | 产品/渠道 | 内核证据 | 策略组 | 结果 |
| --- | --- | --- | --- | --- | --- | --- |
| A | 实际填写 | 实际填写 | 实际填写 | 已核实或未知 | 匿名编号 | 待测 |
| B | 实际填写 | 实际填写 | 实际填写 | 已核实或未知 | 匿名编号 | 待测 |

优先覆盖最低内核、主要安装量、不同 CPU 与有风险的策略组。
不能把全部维度机械做笛卡尔积；按风险裁剪时记录未覆盖项与理由。
新增 CPU 架构、SP、渠道或策略组时，不能沿用未验证的通过结论。

## 分清问题类型

- 上游不支持：目标内核缺少所需能力；选择转译、替代或渐进增强。
- 厂商疑似差异：同版本上游通过、厂商失败；先排除策略、网络、字体和驱动。
- 平台差异：仅特定架构、驱动、字体或桌面会话失败。
- 应用缺陷：构建目标未生效、缓存混版、业务状态或依赖错误。
- 部署限制：证书、CSP、代理、权限、扩展或策略阻止行为。

仅在有最小复现和对照证据后，标注“厂商缺陷候选”。
不要将未知问题直接归因为“国产浏览器不兼容”。

## 输出结论

输出“通过的具体组合、必需功能、已验证降级、已知限制和未测范围”。
发现安全维护风险应单列，不能用兼容性通过替代安全评估。
