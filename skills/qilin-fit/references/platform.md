# 麒麟平台与受管环境

## 定位原则

麒麟、奇安信、CPU 架构、GPU 驱动和企业策略共同决定实际运行环境。
同一 Chromium 主版本仍可能出现字体、文件交互、网络或合成差异。
先获取最小证据，不以更换浏览器或关闭安全措施作为默认修复。
平台排查不等于要求采集设备完整信息；只收集与故障有关的脱敏摘要。

## 系统与 CPU

- 记录 OS 完整发行版、版本、SP、补丁级别与桌面会话。
- 记录实际 CPU 架构，不把 ARM64、x86_64、LoongArch 等视为同一二进制环境。
- 厂商安装包、扩展、本地控件和打印驱动可能只支持部分架构。
- 需要本地组件时，先查官方支持清单、签名、安装来源及权限要求。
- 不下载来历不明的旧包，不建议绕过包签名或系统安全校验。
- 跨架构成功仅说明该架构已测，不能推广到另一个 CPU 平台。
- 如涉及远程浏览或终端代理，区分本地显示端与远程执行端。

## GPU 与图形栈

- 记录显卡、驱动、硬件加速状态与 X11/Wayland 等实际会话。
- 对比静态布局、滚动、视频、canvas/WebGL、滤镜和大面积阴影。
- 黑屏、闪烁、文字消失、窗口拖动异常可能是合成或驱动问题。
- 检查浏览器 GPU 状态和已知问题时，只导出必要脱敏内容。
- 在获准的测试环境中可临时对比软件渲染，定位后恢复原配置。
- 不把全局关闭硬件加速当作未经评估的生产默认方案。
- 大列表、图表和动画须在实际 CPU/GPU 下测响应，不以开发机性能代替。
- 降低动画、减少滤镜或使用分块渲染时，验证功能与可访问性不退化。

## 字库与字体授权

- 确认系统字体实际存在，不能以开发机字体列表作为部署前提。
- 中文正文字体需覆盖业务字符，检查生僻字、标点、数字与回退顺序。
- 验证不同字重、伪粗体、行高、表格对齐与 PDF 导出效果。
- Web 字体必须有合法使用与分发授权，不能直接复制专有系统字库。
- 字体资产需可在内网访问，核对 CORS、MIME、缓存及加载失败后备。
- 字体未加载完成会改变测量结果，canvas、截图和导出须等待所需字体。
- 字体授权不足时提供系统字体栈或经批准的替代，不擅自下载打包。

## 输入法与键盘

- 使用现场实际中文输入法，而非只在英文键盘下测试。
- 验证拼音组合、候选窗、空格选词、回车确认、撤销和多行输入。
- 搜索、快捷提交与表格编辑不要在 composition 阶段提前执行。
- 核查 `isComposing` 与相关事件顺序，使用最小复现定位浏览器差异。
- 检查中英文标点、全角字符、粘贴、换行与输入长度限制。
- 检查快捷键与桌面/输入法的冲突，关键操作保留可见替代入口。
- 虚拟键盘、辅助技术或特殊终端若在范围内，另列验收。

## 剪贴板、文件与 PDF

- Clipboard API 依赖安全上下文、用户操作和权限/策略，存在不代表允许。
- 复制失败时提供可选择文本与手动复制说明，不隐藏失败结果。
- 文件选择器须测取消、重复选择、中文路径名、大文件与多文件。
- 网页不能任意读取本地路径，不以放宽浏览器权限弥补应用设计。
- 下载须测 Content-Disposition、中文文件名、Blob URL 与实际保存结果。
- 及时但不提前撤销 Blob URL；点击触发与资源生命周期需真实验证。
- 受管下载可能经扫描、审批或被阻止，应区分应用、策略与扫描结果。
- 原生文件系统 API 与 `<input type="file">` 支持范围不同，按需给替代交互。
- PDF 检查浏览器预览、下载、打印、字体嵌入、分页与链接。
- PDF 预览插件缺失不能简单认定文件损坏；同时验证下载后的标准阅读器。

## 代理、证书与连接安全

- 区分直连、显式代理、PAC、认证代理和离线部署，记录实际访问链路。
- 核对 DNS、系统时钟、证书链、主机名、有效期与受信任根的合规安装。
- 私有 CA 由管理员按组织流程部署，绝不要求用户关闭 TLS 验证。
- 不把 HTTP、忽略证书错误或全局允许混合内容作为兼容方案。
- 检查代理内容改写、压缩、鉴权和缓冲是否影响前端资源与长连接。
- 客户端证书与密码设备依赖平台中间件时，确认架构与厂商正式支持。
- 涉及国密协议/证书时，记录协议、网关与浏览器发行包的实际能力要求。
- 国密部署不能仅从 Chromium 版本推断，也不要求网站自行降低密码强度。
- 只能通过已授权、合规的证书和网关配置验证，不绕过认证或安全边界。

## CSP 与企业策略

- 分清服务端 CSP、浏览器企业策略、扩展拦截和终端安全软件。
- 检查 script-src、style-src、worker-src、connect-src、font-src、frame-src 等相关项。
- 缺少 nonce/hash、外部脚本被禁、内联样式受限时按最小权限调整应用。
- 不建议全站开启 `unsafe-inline`、`unsafe-eval` 或通配来源来“修兼容”。
- 核对下载、剪贴板、弹窗、摄像头、第三方 Cookie 与文件访问策略。
- 需要管理员调整的策略必须列明影响与授权流程，不由网页绕过。
- 安全软件触发问题时提供最小复现与日志，不指导关闭终端防护。
- 故障对照使用获准的干净测试配置，不改动用户生产个人配置。

## 隔离网络与离线依赖

- 清点字体、图标、脚本、CSS、地图、SDK、遥测和更新检查的外部依赖。
- 经批准后将必要资源纳入内部部署，并遵守许可证与更新责任。
- 不在用户未知情形下把源码、页面内容、HAR 或业务数据发往外部服务。
- 验证首次无缓存访问；联网开发机的缓存命中不能证明离线可用。
- 检查内部资源路径、base URL、子目录部署与 SPA 深链接回退。
- 无法替代的外部服务应明确标识依赖，不伪造本地成功状态。
- 使用 npm 等构建依赖时，按组织批准的仓库与锁文件策略操作。

## 资源加载、MIME 与缓存

- HTML、JS、CSS、字体、Wasm 与 worker 返回正确 Content-Type。
- 模块脚本的 MIME 严格检查失败，不能靠移除 `nosniff` 掩盖错误服务配置。
- SPA 回退不能将缺失 JS/CSS 返回为 200 HTML，需验证深路径与 404。
- 检查 gzip/brotli、缓存头、ETag、代理缓存与内容哈希是否一致。
- HTML 与静态资产混版会造成分包缺失，应采用一致发布与旧资产保留策略。
- 核对 CORS、重定向、Cookie、资源完整性和跨源字体加载。
- 排错时只临时控制测试缓存，不向所有用户永久禁用缓存。

## 长连接、Service Worker 与 PWA

- WebSocket 测试升级握手、代理支持、认证、断线重连与退避。
- SSE 测试响应类型、代理缓冲、空闲超时和页面恢复后的去重。
- 不用无界重连或高频轮询制造额外负载；退路需评估服务端容量。
- 原生 EventSource 的鉴权方式与自定义请求头限制需按具体方案检查。
- Service Worker 依赖安全上下文、作用域与脚本路径，受策略影响时另行说明。
- 测试安装、更新、激活、旧缓存清理与断网恢复，不只看注册成功。
- PWA 安装提示、桌面集成和权限在厂商发行包可能不同。
- 不强制将普通站点改成 PWA；只在项目确有需求时验收。
- 更新或回滚必须考虑已安装 Service Worker，不能只回退服务器文件。
